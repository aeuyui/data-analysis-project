# 2026-2 데이터분석 프로젝트 — 1차 기획서
---

## 프로젝트 주제

런던 공공자전거의 시간·요일·대여소별 이용 패턴 분석과 이동 흐름(출발-도착) 특성 파악

## 프로젝트 배경 및 목적

인공지능학과에 진학하기 전 도시공학과에도 관심이 있었고, 이에 도시공학적인 측면에서 분석할 수 있는 데이터를 찾다 보니 공공자전거 데이터가 많이 제공되는 것을 확인할 수 있었다. 하지만 서울시에서 제공하는 따릉이(서울시 공공자전거) 대여 데이터는 이전에 수강한 과목에서도 본 적이 있기 때문에 다소 식상한 주제라는 생각이 들어 데이터 수집이 가능한 다른 나라 중 런던을 선택하였다. 선택한 'TfL(Transport for London, 런던교통공사) 공공자전거 이용 데이터'는 대여소 단위 이용 기록이 공개되어 있어 사용 패턴을 살펴보기에 쉽다. 이 데이터를 통해 이용이 언제, 어디에 몰리는지 데이터로 확인하고 분석하는 과정을 수행하고자 한다.

## 해결하고 싶은 문제 (왜 이 분석을 하는가)

공공자전거 시스템은 시간대와 장소에 따라 이용이 고르지 않게 나타날 수 있다. 그러나 이용 기록이 여행 1건 단위로 방대하게 쌓여 있어, 원자료만으로는 어떤 대여소가 어떤 시간에 어떤 역할(출발 중심, 도착 중심 등)을 하는지 파악하기 어렵다. 이 프로젝트는 공개 이용 기록을 정리하고 검증해 대여소별 이용 특성과 이동 흐름을 이해할 수 있는 근거를 만드는 것을 목표로 한다.

이 결과는 대여소의 이용 특성과 이동 흐름을 이해하는 기초 자료로서, 이후 운영이나 배치에 대한 논의의 출발점이 될 수 있다. 다만 본 데이터에는 자전거 재고 정보가 없으므로, 운영 개선 자체는 이 프로젝트의 범위에 포함하지 않는다.

## 핵심 분석 질문 (데이터로 무엇을 확인할 것인지)

1. **(패턴)** 시간대와 요일(평일·주말)에 따라 이용량은 어떻게 다르며, 대여소를 이용 패턴에 따라 몇 개 유형으로 나눌 수 있는가?
2. **(흐름)** 출발-도착 대여소 쌍 중 이용이 많은 흐름은 무엇이며, 출발과 도착이 크게 불균형한 대여소는 어디인가?
3. **(대여 시간)** 1회 대여 시간(한 번 빌려서 반납할 때까지)은 시간대, 요일, 자전거 모델, 왕복 여부(출발지=도착지)와 어떤 관련이 있는가?

## 데이터 출처 및 확보 방법

- **데이터셋**: Kaggle, "London Bike-Share Usage Dataset" (https://www.kaggle.com/datasets/kalacheva/london-bike-share-usage-dataset)
- **원출처**: TfL 공식 웹사이트의 공개 데이터
- **확보 방법**: Kaggle에서 CSV 다운로드 (`data/raw/`에 저장, 다운로드 일자 기록)
- **이용 조건**: TfL 공개 데이터의 라이선스와 출처 표기 조건을 확인하여 저장소 README에 기재하고, 표기 조건이 있는 경우 이를 따른다.
- **검증 계획**: 다운로드한 파일의 행 수, 기간, 컬럼 구성을 Kaggle 데이터셋 설명 및 원 출처(TfL)의 공개 자료와 대조해, 사본이 원본과 일치하는지 확인한다. 이 과정에서 확인한 결과는 2차 문서에 기록한다.

## 예상 데이터 규모 및 주요 컬럼 (Kaggle 사이트에서 확인 가능)

- **규모**: 총 776,527행, 기간 2023-08-01 ~ 2023-08-31 (1개월)
- **한계**: 1개월(8월) 자료이므로 계절 변화는 확인할 수 없고, 분석 결과를 다른 기간이나 다른 도시로 일반화하기 어렵다.

**주요 컬럼**

| 컬럼 | 설명 |
|---|---|
| `Number` | 각 Trip의 고유 ID |
| `Start Date` | 한 대여가 시작된 날과 시각 |
| `Start Station Number` | 대여가 시작된 대여소의 고유 ID |
| `Start Station` | 대여가 시작된 대여소 이름 |
| `End Date` | 대여가 종료된 날과 시각 |
| `End Station Number` | 대여가 종료된 대여소의 고유 ID |
| `End Station` | 대여가 종료된 대여소의 이름 |
| `Bike Number` | 대여된 자전거의 고유 ID |
| `Bike Model` | 대여된 자전거의 모델명 |
| `Total Duration` | 대여된 시간 (in a human-readable format) |
| `Total Duration (ms)` | 대여된 시간 (in milliseconds) |

- 데이터 규모와 주요 컬럼 목록은 Kaggle에 기재된 데이터셋 설명 기준이다.

## 예상 분석 방법

### 질문별 분석 방법

| 질문 | 사용 컬럼 | 분석 방법 | 검증 방법 |
|---|---|---|---|
| 1. 패턴 | `Start Date`, 대여소 | `Start Date`에서 시간대·요일·평일/주말 파생 → 시간대·요일별 대여 건수 집계. 대여소별 시간대 이용 비율을 구해 클러스터링(예: K-means)으로 유형화 | 집계 합계가 전체 행 수와 일치하는지 확인, 클러스터 수 선택 근거(엘보·실루엣 등)와 결과 안정성 확인 |
| 2. 흐름 | `Start Station`, `End Station` | 출발-도착 대여소 쌍별 건수 집계, 대여소별 출발 건수와 도착 건수의 차이 계산. "크게 불균형"의 기준은 분포를 확인한 뒤 정의 | 상위 흐름과 불균형 대여소를 원자료에서 다시 집계하여 대조 |
| 3. 대여 시간 | `Total Duration (ms)`, `Start Date`, `Bike Model`, 출발·도착 대여소 | 분포와 이상값 확인 후 시간대·요일·자전거 모델·왕복 여부별 비교, 필요 시 회귀 | Baseline(전체 평균·중앙값)과 비교, Train/Test 분리, Data Leakage 점검 |

### 사전 탐색(EDA) 및 범위

- **일별 이용량 추이**: `Start Date`를 일 단위로 집계해 대여가 특별히 많았던 날이 있는지, 평일/주말 주기가 나타나는지 확인한다. 특별히 많은 날이 확인되면 그 날짜가 공휴일이나 행사에 해당하는지는 공신력 있는 외부 자료로 확인하고, 사용한 출처를 기록한다.
- **시작·종료 시각 경향**: 대여 시작과 종료 시각을 함께 살펴 어떤 경향이 있는지 확인한다.
- **출발만 많은 곳, 도착만 많은 곳**: 질문 2의 결과를 바탕으로 해당 대여소의 특성을 살펴본다. 본 데이터에는 좌표와 토지이용 정보가 없으므로, 지역 특성에 대한 해석은 **대여소 이름 수준**으로 한정한다. 좌표나 주변 시설 등 외부 데이터를 결합한 분석은 확장 계획으로 두고, 결합이 필요하면 해당 데이터의 출처와 이용 조건을 별도로 확인한다.
- **전처리 및 품질 점검(2차)**: 결측치, `Number` 중복, 대여 시간의 비정상 값(0 또는 극단값), 종료 시각이 시작 시각보다 빠른 경우, 자료형을 점검한다.

## 생성형 AI 활용 계획

- 우선 생성형 AI를 사용하여 어떤 분석 방법이 현재 내가 해결하고자 하는 문제에 적합한지 알아보고, 이를 바탕으로 하여 pandas 라이브러리를 활용한 데이터 시각화 코드를 작성할 것이다.
- 생성형 AI가 만들어준 코드를 사용할 때는 실제 표기명과 코드상의 명칭이 일치하는지 확인하고, 이러한 명칭 불일치로 인한 집계 누락이 발생하지 않았는지 확인해야 한다.
- 또한 실제 데이터에 결측치가 있는지 확인하고, 만약 있다면 어떤 방식으로 결측치 치환을 하면 좋을지 데이터의 특성에 맞게 고민해야 한다.
- 마지막으로 결과 해석 부분은 실제 그래프와 데이터를 보고 직접 판단하여 작성한다.
- 생성형 AI와의 대화에 사용된 프롬프트, 생성된 답변, 이를 통해 변경된 사항들은 로그 기록을 통해 별도로 관리한다. 이 기록들은 추후 검증 단계에서 사용될 예정이다.

## 향후 프로젝트 진행 계획

- **2차**: 데이터 확보 결과 확인(컬럼·행 수 대조), 데이터 품질 점검·전처리, 파생 변수, EDA(일별 이용량 포함), 1차 피드백 반영
- **3차**: 클러스터링·흐름·대여 시간 분석, 검증, 한계 정리
- **4차**: 최종 정리
